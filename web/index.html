▲ TAK HUD Prototype

Waveshare ESP32-S3-LCD-1.3-C prism · TAK/CoT · IMU · FLIR Boson · everything in HUD_Dev/

How the pieces fit

The HUD is a small TAK client. It learns where the other units are (CoT from a TAK Server, the ATAK multicast mesh, or a USB-attached phone), where it is (your ATAK phone, later its own GNSS) and which way it is looking (the QMI8658 IMU, later a magnetometer). It then projects every unit into its own field of view and draws it on the prism. Click a box to see what it does and where the code lives.

Click a box.

What exists now

  • Portable C core (firmware/components/hud_core): geodesy, quaternion AHRS, projection, CoT XML + TAK protobuf parsers, target table, NMEA, renderer. 339 host tests pass.
  • ESP-IDF firmware (firmware/): display, IMU, Wi-Fi, TAK TCP/TLS client, mesh SA, USB-phone input, console, live-view API, thermal overlay hooks.
  • Tools: sim_server.py (fake TAK server + scenario + this page), provision.py (TAK .p12 → device settings image).
  • Hardware study: backpack PCB (GNSS/mag), thermal variant, integrated V3 board, Picatinny/M-LOK mount.
  • This page: the HUD simulator uses a JavaScript port of the firmware renderer, pixel-checked against the C output (99.99 %).
The firmware has not been compiled or flashed yet: ESP-IDF isn't installed on this PC. The portable core is compiled and tested with gcc.

Run it

  • Open this file directly, or run python tools/sim_server.py and browse http://localhost:8000 (also gives the HUD a fake TAK server).
  • Host tests: firmware/test_host/run_tests.sh · JS tests: node tests/test_hud_math.js

FLIR Boson thermal & rail mount

  

    

      
Your camera: 21640AS50-6IAER

      
Boson 640 × 512, 50° HFOV (≈41° vertical), shutterless, 60 Hz. 3.3 V, 0.5-1.55 W. Video over 1.8 V CMOS or USB. Control UART 921600.

      
Buy the Boson USB VPC Kit (421-0061-00, ≈$193). It turns the 80-pin connector into a USB-C webcam plus a control port. You need it to configure the camera, and it's the fastest bench path.

      
Getting thermal onto the HUD

      

        
PathVerdict

        
VPC USB → ESP32-S3No. The S3's USB is Full-Speed (12 Mbit/s), and the video needs ~80 Mbit/s.

        
Boson 8-bit CMOS → level shift → S3 camera portYes, 15-30 Hz, cropped to 240². Uses all 13 pins (V2T).

        
VPC USB → ESP32-P4 (USB-HS UVC)Recommended for the rail unit. Full rate, hardware blend.

        
VPC → laptop / PiEasiest for experiments.

      

      
Matching the fields of view

      
      
Try it in the simulator: Thermal → Hot only. Only warm things light up, everything else stays black (see-through), and the camera is rendered from the true pose. So when you add heading error, you'll see the icons drift off the heat signatures. That gap is exactly what thermal-assisted registration would close.

What changes on a rifle

      
    
        
  • Recoil saturates the ±16 g IMU. The firmware already ignores accelerometer corrections away from 1 g. Use a ±2000 dps gyro and hold attitude briefly after a shock spike.
    • 
        
  • Rigidity: Boson, IMU and optic go on one rigid chassis. The rest can be isolated.
    • 
        
  • Barrel steel distorts the magnetometer: calibrate on the gun, mount it high and to the rear, and use boresight alignment as the fallback.
    • 
        
  • Optics: the Waveshare prism isn't collimated. At rail eye relief use a micro-display + eyepiece or a collimated combiner.
    • 
        
  • This is a situational-awareness display (TAK plus thermal), not an aiming device.
    •

First steps with the board

      
    
        
  1. Install ESP-IDF v5.3+, then cd firmware && idf.py set-target esp32s3 && idf.py build.
    2. 
        
  2. idf.py -p COMx flash monitor (the CH343 COM port). It boots into fake targets: rotate the board and the units should stay put in the world.
    3. 
        
  3. Console: wifi <ssid> <pass>, tak <pc-ip> 8087 tcp, own uid ANDROID-SIM-OWNER, save, reboot, with python tools/sim_server.py running.
    4. 
        
  4. Calibrate: cal level, then pitch the nose up and cal nose, then mode 2 to measure FOV, then fov / bore, then save.
    5. 
        
  5. Real TAK Server: python tools/provision.py … --proto tls --client-p12 HUD-001.p12 --truststore truststore-root.p12 and flash hudcfg.bin.
    6.

BOOT key

      
Short press: next display mode. Double press: thermal Off/Full/Hot. Long press: align heading to the unit in the crosshair (in Calib mode, trim level).

Accuracy you should expect

    
2° of heading error puts an icon ~35 m off at 1 km, and GPS error of a few metres matters most for nearby units. That makes this a geo-referenced cue display, not precision AR. Magnetometer calibration, RTK or dual-antenna GNSS, and thermal-assisted snapping to heat signatures are the upgrade path. Try the error sliders in the simulator.
